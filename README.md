# ResNet34 + U-Net++ Breast Lesion Segmentation

This project trains **separate breast lesion segmentation models** for:

1. **Mammograms**
2. **2D breast MRI slices**

Both experiments use a **U-Net++ decoder with a ResNet34 encoder**, but they are trained independently with separate datasets, preprocessing settings, checkpoints, and training histories.

The task is formulated as **binary semantic segmentation**:

- `0` = background
- `1` = breast lesion

## Important: Split by Patient

Create the `train`, `val`, and `test` splits **before running the script**.

Splits should be performed at the **patient level**, not at the individual image or slice level.

This is especially important for MRI data. Multiple slices from the same patient's MRI volume must not appear in different splits because this can cause **data leakage** and artificially increase the reported performance.

For example:

```text
Patient 001 -> train only
Patient 002 -> train only
Patient 003 -> validation only
Patient 004 -> test only
```

Do **not** place some slices from Patient 001 in training and other slices from Patient 001 in validation or testing.

## Image and Mask Naming

Each image must have a corresponding mask with the same base filename.

For example:

```text
images/
├── patient001.png
├── patient002.png

masks/
├── patient001_mask.png
├── patient002_mask.png
```

The loader recognizes common mask suffixes including:

```text
_mask
-mask
_seg
-seg
_label
-label
```

Therefore:

```text
patient001.png
patient001_mask.png
```

will be treated as a valid pair.

Masks are converted to binary masks using:

```python
mask > 0
```

Any non-zero mask value is therefore considered part of the lesion.

# Model Architecture

## Overview

The model consists of:

```text
Input Image
    ↓
ResNet34 Encoder
    ↓
Multi-scale Feature Maps
    ↓
U-Net++ Nested Decoder
    ↓
Deep Supervision
    ↓
Binary Lesion Segmentation Mask
```

---

## ResNet34 Encoder

The encoder uses a pretrained **ResNet34** from `torchvision`.

The encoder produces feature maps at multiple spatial resolutions:

```text
conv1   -> 64 channels
layer1  -> 64 channels
layer2  -> 128 channels
layer3  -> 256 channels
layer4  -> 512 channels
```

By default, ImageNet pretrained weights are used:

```python
ResNet34_Weights.DEFAULT
```

### Grayscale Medical Images

Standard ResNet34 expects 3-channel RGB input.

For single-channel mammograms and MRI slices, the first convolution is modified from:

```text
3 input channels
```

to:

```text
1 input channel
```

The pretrained RGB convolution weights are averaged across their three channels to initialize the grayscale convolution.

---

## U-Net++ Decoder

The decoder uses the **nested dense skip connections** characteristic of U-Net++.

Conceptually:

```text
x0,0 ───── x0,1 ───── x0,2 ───── x0,3 ───── x0,4
  ↓          ↑           ↑           ↑           ↑
x1,0 ───── x1,1 ───── x1,2 ───── x1,3
  ↓          ↑           ↑           ↑
x2,0 ───── x2,1 ───── x2,2
  ↓          ↑           ↑
x3,0 ───── x3,1
  ↓          ↑
x4,0
```

The ResNet encoder provides the `x(i,0)` features, while the remaining nodes are generated by the U-Net++ decoder.

Unlike ordinary U-Net, U-Net++ progressively refines the semantic gap between encoder and decoder feature maps through nested convolution blocks.

---

## Deep Supervision

Deep supervision is enabled by default.

The model produces intermediate segmentation outputs from:

```text
x0,1
x0,2
x0,3
x0,4
```

During training, the loss is computed for all four outputs and averaged.

The final output `x0,4` is used for segmentation metrics and final prediction.

---

# Loss Function

The project uses a hybrid:

```text
Binary Cross-Entropy + Dice Loss
```

The default formulation is:

```text
Loss = 0.5(BCE) + 0.5(Dice Loss)
```

These weights can be changed independently in each dataset configuration:

```python
bce_weight=0.5
dice_weight=0.5
```

BCE handles pixel-wise classification, while Dice loss directly encourages overlap between the predicted lesion region and the ground-truth mask.

## Multi-Channel MRI Input

The current MRI configuration assumes a single-channel 2D image:

```python

```

If each MRI slice contains multiple aligned modalities/channels stored in a NumPy array, the model can be changed accordingly.

For example:

```python

```

for an input shaped approximately as:

```text
4 × H × W
```

The ResNet34 first convolution will automatically be adapted to the specified number of input channels.

# Optimizer and Learning Rate

Training uses:

```python
AdamW
```

with the default:

```text
Learning rate: 1e-4
Weight decay: 1e-5
```

A `ReduceLROnPlateau` scheduler monitors validation Dice.

If validation Dice stops improving, the learning rate is reduced.

---

# Model Selection

The best checkpoint is selected according to **validation Dice score**.

A new checkpoint is saved whenever:

```python
val_metrics["dice"] > best_val_dice
```

This avoids selecting the model based on the held-out test set.

The test set is evaluated only after training is complete and the best validation checkpoint has been restored.

---

# Evaluation Metrics

The code calculates:

- **Dice coefficient**
- **Intersection over Union (IoU)**
- **Precision**
- **Recall / Sensitivity**
- **Pixel accuracy**
- **BCE + Dice loss**

For medical image segmentation, Dice, IoU, recall, and precision are generally more informative than pixel accuracy because the background region can contain far more pixels than the lesion.

Predictions are converted into binary masks using a default probability threshold of:

```text
0.5
```

# Current Model Scope

The current implementation is intended to serve as the **ResNet34 + U-Net++ baseline model**.

It currently includes:

- ResNet34 encoder
- U-Net++ nested decoder
- Deep supervision
- BCE + Dice loss
- Separate mammogram and MRI pipelines

It does **not yet include CBAM**.

A future modified architecture can insert CBAM modules into the U-Net++ skip pathways and then compare:

```text
ResNet34 + U-Net++
        vs.
ResNet34 + CBAM-enhanced U-Net++
```

Keeping the baseline separate makes it possible to evaluate whether the addition of CBAM produces a measurable improvement.

---

# Suggested Experimental Workflow

A reasonable experimental sequence is:

```text
1. Prepare patient-level train/validation/test splits
2. Verify image-mask pairing
3. Train ResNet34 + U-Net++ on mammograms
4. Evaluate the best mammogram checkpoint
5. Train a separate ResNet34 + U-Net++ model on MRI slices
6. Evaluate the best MRI checkpoint
7. Record baseline Dice, IoU, precision, and recall
8. Add CBAM to the selected skip pathways
9. Repeat both experiments
10. Compare baseline and CBAM-enhanced models
```

Mammogram and MRI results should be reported as separate experiments rather than combining their metrics.
